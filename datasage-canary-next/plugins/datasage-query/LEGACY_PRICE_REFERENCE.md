# 旧数据库价格参考与HT数量

旧参考明确存在于 `vk_ai.ready_goods_price_snapshot`（销售）和
`vk_ai.ready_goods_purchase_snapshot`（采购）。此前只读本地accepted.json造成的冷启动判断
已经纠正。固定生产价格工作流默认 `reference_source: legacy_database`；一般operations调用
也可以显式选择这一只读来源。旧表不更新，也不会隐式接受新本地基线。

比较在同一只读一致性快照内读取数据库时钟、旧参考和当前原四区域业务池，均有10000行限额。
检查主键/业务键重复、NULL与空可选键、快照时间、当前候选歧义、币种及可用单位口径。
超限/旧键重复/未来快照时间直接拒绝，NULL价格不当零。

- 销售旧键：goods_id/dept/customer_grade/color_label。旧表保存DDP、币种和报价明细ID，
  **没有历史unit、unit_cuur、is_inclue_tax、有效期**；相同明细ID也不证明这些字段从未被改动。
  只比较同币种的名义DDP字段，发生变化时在验收说明中标出历史单位/税口径未验证。
- 采购旧键：goods_no/color_label/supplier_no。币种、计价单位一致后分别比较含税/未税价。
  历史有效期未记录，消息只说明记录报价变化，不擅自认定为当前可执行采购价。
- 新键不生成变价，旧键未在现池出现不表示报价被撤销；身份或价格未知单列。
- 无变化不发送；有变化先按原销售/管理层与买客规则形成逻辑通知，再按验收模式选最多两份完整
  通知。采购原外部user/webhook选择未取得时，仅发明确说明的测试成员核验稿，不编造生产群路线。

源表原snapshot_at与观察时间、比较层级、缺失历史字段均保留。事件身份不包含每次重写的
snapshot_at，避免旧快照仅刷新时间就造成重复提醒；实际当前源修改时间与价格值仍参与事件证据。
旧快照写入方及正式切换时谁负责基线推进，仍需协调，不能因只读适配完成就开启生产调度。

## HT高折分单位数量

复用原高折条件（严格大于原合同阈值）和原合格退货口径：
`高折净数量 = 符合高折条件的毛出库数量 - 全部合格退货数量`。
每个m/y/kg/Pcs单位独立计算，保留负数；不与普通净数量相加，不跨单位合计。
价格、高折数量、退货数量或候选范围不完整时完整值为Unknown，同时保留已知部分。
低价行缺数量不污染已知高折数量；缺卷数不抹掉可计算的数量字段。

新增组级和单位总体字段及数量缺失计数，登记在inventory语义契约中。HT报表的高折数量、
销售分单位数量和独立单位汇总均核对；完整报表仍检查其他展示字段，遇到缺失不会强标完整。

新CLI `datasage_region_acceptance.py` 只允许原其余七部门，分task/weekly/monthly准备。
HCM不在此入口，避免重复既有样本；prepare不发送，monthly发送要求本部门weekly已接受。
真实无库存任务行仅表示该部门无选中冻结任务，不宣称物理库存为零。所有发送继续锁定验收目标。

Profile代码和语义契约在新启动的本地验收进程中验证；没有重载既有网关，也没有修改官方源码。
