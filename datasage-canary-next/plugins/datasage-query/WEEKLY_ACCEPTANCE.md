# HCM 单部门周报本地验收

固定入口 `scripts/datasage_weekly_acceptance.py`，无参数或额外参数均拒绝，不做查询。
以后明确授权只读验收时，才在本 Profile 的 `HERMES_HOME` 下使用官方 Python 执行
`datasage_weekly_acceptance.py --read-hcm-2026-w38`。这不是本次已执行的命令。

范围固定为 HCM / 2026-W38 / weekly，无任意SQL、路径、部门、周标签或收件人参数。
本机操作员上下文检查、物理 Profile 匹配、既有运行配置加载仍执行。
不依赖或改变生产激活开关，不读取原收件名单，不调用月报、发送、冻结、写库、价格接受
或调度。正常路径只生成本地文字、Detail XLSX、数据证据和验证记录。

## 数据取得与完整性

`report_evidence.collect` 仅生成政策内部门和周/月周期的四个固定报表请求：
池明细、规格/销售流水明细、按单位池汇总、按单位流水汇总。
复用现有结构/业务预检、运行就绪检查、查询并发槽、编译器、`_run_one` 验证/审计、
只读一致性快照和有界 JSON 编码；不是新数据库连接器或通用权限绕过入口。
四份结果及标签读取共用一个快照和绑定的数据库观察时钟。标签只读指定部门的 SKU、货号、颜色、部门，
不读客户名录、人员名录或价格字段。月报补读同一库存快照月份、报表SKU范围内的历史标签；冲突仍列为歧义。

发现并修复旧 `report_inputs` 的 limit=1000：实际公开契约上限为100，旧请求不合法。
每页固定limit=100，不扩大公开配置、SQL权限或每页wire边界。固定报表内部最多20页，在同一快照/固定时钟下，验证稳定排序、查询签名、连续偏移和完整覆盖后合并。任意缺页、超限、JSON裁剪/失败、重复粒度或快照成员不符均拒绝完整报告。标签读取原有上限10000也不扩大。

验证项：
- 四份成功结果、返回行数、截断标志、请求ID、周期、相同冻结时点、同一快照成员。
- 池总体组数与实际唯一明细数；流水总体组数、分单位组数；稳定 SKU/部门/单位/销售身份去重。
- 池明细与独立单位汇总的状态数量、期初/期末组数、数量、卷数。
- 流水必须属于期初池；各单位期初覆盖数量、净数量、净卷数、高折扣净卷数、出库/退货事件数。
- 跨单位卷数和各销售总卷数；未知数值不填零；只有独立零事件汇总支持时空销售明细才可为零。
- 适配后再执行既有 `validate_complete_detail`。没有独立证据的直接格式适配仍不标完整。

`detail_complete=true` 表示本次池/流水人群和数量对账通过，不等于标签完整，也不声称金额完整。
本报表不计算金额，明确 `amounts_applicable=false`。标签以货号/颜色唯一性单独统计
missing_groups、ambiguous_groups；名称不参与数值主键或数量去重。
标签不全时本地只输出 `REVIEW_ONLY` 和覆盖说明，数值仍保留；生产发送阶段拒绝该报表。
数值/覆盖失败时不生成成功样式工作簿，仅留下拒绝记录。

所有本地报表写明“截至观察时点、非全周最终结果”；固定W38入口在观察时点不属于W38时拒绝，
防止后续拿当前库存伪装该历史周末库存。库存状态变化与净出库继续分别解释。
规格计数基于源登记 SKU/部门/单位组，不通过缺失/同名的展示标签折叠。

## 生产兼容与剩余限制

生产 slow_report 仍按八部门、先全部周报后月报；每个阶段先验证各部门结果，再开始输出和发送。
独立入口只走 HCM weekly，不把 target_map 当收件人过滤器。现有应用发送和冻结代码未改动。

以下仍未实现，不归因于开关：
- 超过2000个展示组或整体时间/wire预算仍会停止，不做无界分页。
- 没有可核验行级总体证据的完全空池，保守拒绝为完整报告，不能推断为正常零库存。
- HT 的 high_net_qty_by_unit 已按来源单位独立补齐并与明细/单位汇总核验；其余七部门通过regional_acceptance入口分批检查，不能仅凭HCM结果代替其他部门。
- 同月库存快照也缺失或存在冲突的历史标签仍会Unknown，必须按覆盖复核，不能凭当前产品主表补造历史值。

自动化测试使用合成SQLite/模拟I/O。后续真实数据及指定测试目标验收遵循独立REMINDER_ACCEPTANCE模式的授权和证据记录；生产开关、冻结/写库、价格基线接受和调度仍分开授权。
