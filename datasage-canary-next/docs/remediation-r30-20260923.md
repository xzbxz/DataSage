## 1. 结论

- **维护面已实测**，且**只统计受跟踪的已复核版本**（`git ls-files`）：这样任何 checkout 都能
  复现同一组数字，也符合本 profile「以已复核提交为真源」的一致做法。数字由

- **受跟踪文件里没有孤儿候选**（0 个）：所有受跟踪的模块、夹具与文档都至少被其它文件提及。

  它们不是「孤儿」也不是「无用」——只是**没有进入已复核范围**。新增未跟踪文件会被守卫拦住
  （未声明即报错）。
- **no-deletion 政策可追溯**：受保护清单（回执测试、审计与发布记录、规则归属清单、运营入口台账、
  外部核验登记册）由守卫校验**仍然存在**，禁止以维护量为由删除；「未用不等于无用」写在策略里。
- **变更成本已量化**（实测扇出 + 真实提交历史），见第 4 节。
- 本轮自查修掉 5 处测量 bug（含 1 处会写入错误控制字符的补丁事故），见第 5 节。

## 5. 本轮自查修掉的测量缺陷

1. 模块引用检测只认 `from .mod import` 与带引号的名字，漏掉 `from . import a, b` 与
   `import_module(f"{PACKAGE}.mod")` 形态 → 曾报出 8 个假孤儿；改为**词边界提及**计数。
2. 指标引用靠猜前缀 → 只找到 6 个；改为以 R16 登记册的全量码表逐词匹配（63/215）。
3. `git log` 的 pathspec 用了仓库根相对路径，而 `-C` 已进入 profile 子目录 → 中位数全部为 0；
   改为 profile 相对路径后得到真实中位（6/4/5）。
4. 补丁脚本把 `\b` 写成了**退格控制字符**，导致检测恒为 0；`cat -A` 定位后修正。
5. 自指测量：登记册自身在 `fixtures` 计数内，写一次数字就变一次 → 排除自写文件，`write→check`
   现为幂等。
6. **R31 回退演练暴露的两处不可复现**（同轮修掉）：R28 体量守卫对**行尾**敏感（克隆 LF 与本机
   CRLF 差 50 字节）、R28/R30 统计含**未跟踪文件**（克隆里少 4 篇文档即失败）→ 测量对象改为
   受跟踪的已复核版本 + 归一化行尾字节数，未跟踪文件单列待决策。同时纠正一处**登记册写早一步**：
   我先把 R30 文档写进登记册、之后才补导出器白名单，导致登记册把已被引用的文档误列为孤儿候选；
   重测后孤儿候选归零，那两篇验收文档重新归类为未跟踪外挂。
