# R28 核验记录：质量约束下的上下文与成本对照

日期：2026-09-23｜依据：综合审查 V2.0 的 R28（批次 F / P2）｜负责角色：平台管理员＋开发
前置：R05、R11、R20、R25（已完成）｜性质：可复现实测 + 未测项声明 + 降级点清单；真实 token/延迟/账单待回放

## 1. 结论

- **只列实测数字**：本轮所有数字由 `tests/context_cost.py` 从本工作区现算（`measure`／`write`／
  `check`），任何审阅者可复跑复现；**没有**用字节数换算冒充 token 数，也没有预测延迟或成本。
- **质量门未动**：R19（24 案盲评）、R20（答案类型最小内容）、R16（数值真值登记）三条门在登记册里
  标为 `unchanged`，并由守卫校验其引用文件存在；策略里明写「成本改动不得放宽质量门」。
- **降级点分两类**：3 项「已生效」（含实测或测试证据）、2 项「候选未实施」（含触发条件、主人与
  所需证据，`applied=false`）。
- 有一处测量方法被当场纠正：目录 payload 最初的调用不合法（两次都只拿到 114 字节的失败信封），
  修正为合法调用并加自检——**失败信封不得计入测量**。
