# R20 核验记录：统一业务表达并复用报告证据

日期：2026-09-23｜依据：综合审查 V2.0 的 R20（批次 D / P1）｜负责角色：业务产品＋交付开发
前置：R13、R16（已完成）｜性质：展示层要求补齐 + 同源一致性行为测试；真实渠道评审待做

## 1. 结论

- 展示层的**同源与保真其实已有机制**：本机报表由同一返回结果渲染，且有 14 项用例覆盖
  单位保留、期间不混、超时不当零、截断与未知项披露、基线陈旧不静默替换等。
  实测确认：渲染与产物都来自同一个结果对象，展示过程不改写证据。
- **缺的是「按答案类型的最小内容」这条书面要求**：原来的 `Response shape` 是通用规则，
  没有区分问数／解释／诊断／管理层报告各自至少要带什么。
- 本轮在 `answer-boundary.md` 补 `## Minimal content by answer type`（四类各写最小内容 +
  共同规则），并新增 4 项行为测试把「同一结果、可重复、未知≠零、同源产物」钉住。
- 未引入 Report IR、Finalizer 或任何模板框架；未改指标口径，只动展示层要求。

## 3. 四类答案的最小内容（新增要求摘要）

| 类型 | 至少要带 | 明确不要求 |
| --- | --- | --- |
| 问数 | 返回值 + 单位/币种 + 实际返回期间或快照 + 指标业务含义 + 适用的披露（贴在对应结论旁） | 不要求铺陈叙述；一个受管结果就够 |
| 解释 | 上述事实 + 为什么可比（口径/期间/账本/总体）+ 仅限完整对账授权的结构贡献 | 不得把「解释」升格为原因 |
| 诊断 | 事实 + 标记为假设的候选解释 + 能区分它们的证据 + 证据不足时的下一步核对 | 不给固定路线、不强制全域同深 |
| 管理层报告 | 选定事实及其范围行 + 每个分支的状态（含失败/截断/未完结）+ 动作的条件、风险与审批人；本渠道不能产出文件时明确说明并给 operator 路径 | 不强制章节结构与建议条数 |

共同规则：复用本轮对话已返回的事实而不是重查；陈述**实际**返回范围而非请求范围；
未知/空/未完结/失败一律不得渲染为零；数字、单位与表格必须与同一返回结果一致。
