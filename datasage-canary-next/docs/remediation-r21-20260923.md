# R21 核验记录：多轮纠正、压缩与共享记忆隔离

日期：2026-09-23｜依据：综合审查 V2.0 的 R21（批次 E / P1）｜负责角色：宿主测试＋数据 owner
前置：R02、R14、R15（已完成）｜性质：机制核验 + 行为规则补齐；真实双人会话回放待做

## 1. 结论

- **会话隔离是宿主的既有机制，且按成员隔离**（实测，非文档推断）：
  - 私聊键为 `agent:main:wecom:dm:<成员id>`，与线上网关日志里写的键**逐字一致**；
  - 同一群内两名成员得到**不同**的会话键（`…:group:<群id>:<成员id>`），宿主默认按成员分会话；
  - 成员甲的键不含成员乙的 id，反之亦然；
  - 指定 profile 时命名空间变为 `agent:<profile>:…`，两个 profile 服务同一会话不会串。
- **压缩不丢关键信息的宿主链路复跑通过**：宿主压缩 E2E 3 项（含真实宿主一次性子进程链路）全绿。
- **缺的是行为规则**：本次核验前，Skill/边界文件里没有「最新纠正优先、事实时间标明、临时查询
  不进共享长期知识、压缩后保留单位/权限/限制、成员会话互不可见」这几条明文。本轮补进
  `answer-boundary.md` 并加守卫测试。
- 离线不能替代的部分（真实双人会话、网关重启回放、引用旧报告、模型从历史取旧值）列在第 5 节，
  未标记为通过。

## 3. 本轮新增的行为规则（answer-boundary）

| 规则 | 内容 |
| --- | --- |
| 最新纠正优先 | 用户更正实体/期间/账本/范围时，新说法取代旧说法；不得继续用已废弃范围，也不得悄悄取两者平均 |
| 事实时间标明 | 每个数字给**实际返回**的期间或快照，而不是请求或默认范围；当前观测不得当成已结束期间 |
| 成员会话互不可见 | 不得把一个成员的内容带进另一个成员的回答；保留的会话不是共享数据的沙箱 |
| 临时查询不沉淀 | 聊天里问过的问题本身不是要记住的事实；写入共享长期知识（Memory/Skill）必须走 R14 的审批闸门，临时查询留在其会话内 |
| 压缩保留要点 | 单位、权限、类型化状态与限制性披露必须在压缩后存续；摘要与返回证据冲突时以证据为准 |

补充事实（需 owner 知情）：本 profile 的 Memory 是**profile 级共享**文件；由于企微渠道不含
memory 工具（R13 实测 7 个工具），临时查询无法从渠道写入共享记忆。CLI 侧仍可写且受审批约束。
