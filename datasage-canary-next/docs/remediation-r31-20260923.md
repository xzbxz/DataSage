## 4. 回退与恢复演练（已执行）

| 步骤 | 动作 | 验证 |
| --- | --- | --- |
| rb_1_freeze | 停止扩围：不注册调度、不打开发送开关 | bindings 开关全为 false 且无 cron 作业 |
| rb_2_revert | 在克隆/工作区回退到已复核提交 | 变更集 10 个文件整体回退、工作区干净；回退后**有一个守卫为红**（变更前版本的测量实现不可移植到干净 checkout），恢复后全部转绿 |
| rb_3_config | 配置以受跟踪的已复核版本为准 | `git status --porcelain config.yaml` 无差异 |
| rb_4_restore | 恢复并复跑守卫 | HEAD 与回退前一致、工作区干净、守卫全绿 |

演练记录（`tests/fixtures/gray_release_plan.json` 的 `rollback.rehearsal`）包含：
克隆方式、回退前/恢复后的提交、变更集与回退文件数（10 = 10，整体回退）、三态下每个守卫文件的
返回码与失败原因。**演练只在本地克隆中进行**，线上 profile 未被回退或修改。
守卫语义：回退前与恢复后必须全绿；回退后允许有守卫为红，但**必须记录失败原因**（否则守卫报错）。
记录另含一次**复验**（`rollback.rehearsal_reconfirm`）：环境感知修复后重跑同一演练流程，回退/恢复同样干净、三态守卫全绿。

## 5. 演练暴露并修掉的缺陷（重要）

| 缺陷 | 现象 | 修法 |
| --- | --- | --- |
| R28 体量守卫对行尾敏感 | 克隆（LF）与本机工作区（CRLF）测出 `plugin.yaml` 字节数差 50 | 改测**归一化行尾后的文本字节数** |
| R28/R30 统计含未跟踪文件 | 克隆里少 4 篇未跟踪文档 → 守卫在克隆中失败 | 统计对象限定为**受跟踪的已复核版本**（`git ls-files`），未跟踪文件单列为「待决策外挂」 |
| R30 登记册写早了一步 | 我先把文档写进登记册、之后才补导出器白名单，导致登记册把已被引用的文档误列为孤儿候选 | 重测后孤儿候选归零；那两篇验收文档重新归类为**未跟踪外挂**（更准确） |
| 非仓库副本无法判定「受跟踪」 | 纯文件副本（无 `.git`）里统计口径与登记册不同 → 守卫在副本中失败 | 守卫改为**环境感知**：在 git 工作树内做严格比对；非仓库环境改为校验「所有面都声明来自已复核提交 + 记录的文件确实存在 + 保留清单完好」，并显式跳过严格比对（`skip` 可见，不假装已比对） |

新增守卫会拦住未声明的新外挂：任何未跟踪文件出现在 profile 里而没在登记册声明，守卫即报错。
