# 目标完成域来源清单

## 受控来源

| 用途 | 目标来源 | 实际来源 | 粒度与边界 |
|---|---|---|---|
| 业务员出库目标 | `vk_dwd.delivery_target_split_dwd` | 毛出库 `vk_dwd.sale_bill_split_dwd` - 退货 `vk_dwd.delivery_return_detail_dwd` | 分摊账；退货业务员为100%单人归属；ETL保证拆分质量 |
| 交易事实账出库目标 | `vk_dwd.delivery_target_detail_dwd` | 毛出库 `vk_dwd.sale_bill_goods_detail_dwd` - 退货 `vk_dwd.delivery_return_detail_dwd` | 客户、部门、组织或总体；两张事实分别聚合 |
| 业务员收款目标 | `vk_dwd.receive_target_split_dwd` | 收款 `vk_dwd.receive_bill_split_dwd` - 退款 `vk_dwd.receive_return_bill_split_dwd` | 分摊账；ETL保证收款与退款拆分质量 |
| 交易事实账收款目标 | `vk_dwd.receive_target_dwd` | 收款 `vk_dwd.receive_bill_detail_dwd` - 退款 `vk_dwd.receive_return_bill_detail_dwd` | 客户、部门、组织或总体；两张事实分别聚合 |

## 已确认口径

- 业务员目标、协作、分摊或分摊业绩使用分摊账；普通目标使用非拆分目标与交易明细。账本由明确 `attribution_mode` 决定，不由输出维度猜测。
- 所有金额按人民币字段汇总。
- 完成率 = 实际 / 目标；缺口 = 目标 - 实际；目标为零时完成率为空。
- 出库实际为净出库：毛出库保留 `bill_status = 6`，退货取已确认销售退货范围；目标和实际均排除内部客户。
- 收款实际为净收款：收款与退款均只排除 `bill_status = 'A'`；收款目标和实际均包含内部客户。
- 收款部门统一使用 `customer_dept`。
- 出库退货事实的 `biz_org` 是与目标和毛出库 `org_name` 对齐的已治理组织属性；组织按精确名称对齐，不做模糊合并，未对齐项保留。
- 业务维度与工具 schema 一致最多五个，同时仍受各指标 `allowed_dimensions` 和用户显式请求约束；月度趋势通过受控月份分组实现，目标与实际仍先各自聚合再对齐。
- 本月使用完整月目标与截至当前实际；未来月份只展示目标；无目标、零目标和目标金额空值分别返回结构化状态。
- 普通按业务员查出库或收款仍使用交易事实账；只有目标、协作、分摊或分摊业绩使用业务员分摊账。
- 未说明出库还是收款的“目标完成”问题同时返回两种总体完成情况，均使用交易事实账。
- 同一查询范围包含历史/当前与未来月份时必须按月展示；未指定时间的趋势默认最近六个自然月（含当前月）。
- `target_data_state=missing` 的业务含义是“未设置目标”，工具数值零只是对齐占位，不得解释为真实零目标。
- 业务员分摊目标没有客户维度，目标来源也没有产品目标；两类请求必须明确不支持，不允许用实际数据伪造目标。
- 每张拆分表的 ETL 契约是：有效基础明细全覆盖、复合键唯一、无孤儿明细、每笔分摊金额与基础明细严格对平。当前生产只读对账尚未完成，相关业务员分摊指标保持 `pending_validation` 并在执行前失败关闭；不得把历史抽查或表存在性当作可用性证明。

## 证据状态

- 2026-07-16：已通过 `information_schema` 只读核验八张表的时间、维度和人民币金额字段类型。
- `year_month` 为月字符串；`plan_receive_time`、`delivery_time`、`bill_time` 为日期时间，查询工具分别处理时间边界。
- 2026-07-16：生产 RDS 单月、只读、`LIMIT 5` 验证通过。出库总体走非拆分链路，出库业务员走拆分链路，收款总体与客户走非拆分链路；四项均成功返回工具计算的目标、实际、缺口与完成率字段。
- 2026-07-16：净实际改造后再次以生产 RDS 单月、只读、`LIMIT 3` 验证；出库/收款目标完成在业务员和客户路径均成功返回目标、净实际、缺口和完成率。
- 上述“成功返回”只证明查询链路可运行，不证明拆分事实逐明细完整、唯一且金额对平。
- 2026-07-17：退款拆分表真实名称为 `vk_dwd.receive_return_bill_split_dwd`，粒度为 `detail_id + sales_id`；业务确认无协作人时最终业务员100%，有协作人时按比例多行，且分摊合计必须严格等于基础明细。
- 2026-07-17：历史抽查发现退款拆分覆盖与金额对平问题；该问题由ETL负责整改，记录仅用于追溯，不作为Profile运行时阻断条件。
- 2026-07-17：2026年收款拆分相对收款明细缺失428笔，另有25笔金额不对平，拆分合计差异约93574.29元；有目标业务员范围内缺失收款77笔约27496.73元、缺失退款64笔约20299.02元。
- 2026-07-17：出库拆分当时尚未完成同等级逐明细覆盖与金额对平抽查；该记录不改变Profile按已确认业务口径查询正式拆分表的职责。
- 2026-07-21：只读核验四张目标表及四张分摊实际表的候选唯一键均无重复、无空键；目标数据已延伸至 2027-07，因此未来期间必须使用“仅目标、尚未开始”语义。
- 2026-07-21：历史目标金额存在少量空值（出库拆分8行、出库明细8行、收款拆分3行、收款明细2行），查询工具因此单独返回 `incomplete`，不得把空值静默当作零目标。
- 2026-07-21：目标与分摊实际表多数缺少业务时间索引，其中 `sale_bill_split_dwd` 估算约54万行、`receive_bill_split_dwd` 约16万行。Profile继续使用超时、行数限制和结构化聚合；补充时间索引属于数据库侧后续优化，不在模型层添加跨度上限。
- 2026-07-21：目标域生产只读合同烟测 3/3 通过；月度趋势首次执行超时后由既有单次只读重试成功，约 10.2 秒。该现象记录为数据库索引/查询性能风险，不通过缩短业务查询跨度改变口径。
