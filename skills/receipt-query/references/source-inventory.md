# 收款与退款语义来源

## 当前权威来源

- `semantics.yaml`：收款、实收、退款、实退、单数、原币和净收款指标及维度。
- `common-data-foundation/references/datasets.yaml`：收款明细和退款明细的粒度、主键、允许字段及客户主数据受控关联。
- 已确认规则：只排除 `bill_status=A`；包含内部客户；默认包含全部收款用途，只有用户明确限定时才筛选用途；部门统一为 `customer_dept`、组织为 `org_name`、业务员为 `final_sales_id/final_sales_name`。
- 已确认金额规则：收款人民币使用 `detail_receive_rmb`；实收人民币为 `detail_deal_amount × exchange_rate`；退款人民币使用 `detail_return_rmb`；净收款为收款人民币减退款人民币；“到账”默认指收款人民币。
- 普通查询使用交易事实账：收款 `receive_bill_detail_dwd`、退款 `receive_return_bill_detail_dwd`，按各自 `final_sales_id/final_sales_name` 归属。
- 只有目标、协作、分摊或明确分摊业绩才进入目标域的业务员分摊账；本域不直接使用收退款拆分表。

## 开放分析可用证据

- 汇总：收款、实收、退款、净收款及单据数。
- 趋势：按日或按月展示指定指标，净收款由工具分别聚合两侧后计算。
- 排名与结构：客户、业务员、部门、组织、用途和结算方式等受控维度。
- 前期比较：同一指标和维度的当前期间与等长前期，返回当前值、前期值、差额和变化率；复合净收款也在工具层完成。
- 单客户分析：以客户过滤复用已确认指标，不引入临时口径。
- 普通收退款概览：只展示收款、退款和净收款；实收、实退仅在用户明确询问时查询。
- 生产只读链路已验证：收款/实收/退款/净收款概览、净收款月度趋势、按部门的净收款等长前期比较和收款用途结构均成功执行。
- 2026-07-16：部门切换为 `customer_dept` 后再次通过生产只读验证；净收款部门比较返回结构化 `customer_dept` 字段。

## 限制

- 收款、实收和净收款是不同业务含义，不能混称。
- 默认包含全部收款用途和内部客户，回答必须说明。
- 客户电话和联系地址在当前候选版本中不进入模型可见合同或查询结果；恢复前必须具备用户级授权和用途控制。
- 当前客户主数据属性不是交易时点快照。
- 回款变化不能单独证明催收效果、客户付款意图、风险或人员绩效。
- 完成率和目标问题属于目标域，本域不临时拼接目标。
- 当前人员主数据只可补充当前属性；已确认事实业务员通过 `sales_id/final_sales_id = employee_dwd.person_id` 关联，但人员表的重复状态解决前禁止直接参与金额指标关联。

本文件只记录规则来源和能力边界，不保存客户、收款单或金额明细。
