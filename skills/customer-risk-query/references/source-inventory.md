# 客户应收风险语义来源

## 当前权威来源

- `receivable-query/references/semantics.yaml`：欠款、账龄、未结清、逾期、授信和无授信欠款的已确认口径。
- `delivery-query/references/semantics.yaml`：净出库金额及客户、部门、业务员、组织维度。
- `receipt-query/references/semantics.yaml`：净收款人民币口径。
- `common-data-foundation/references/datasets.yaml`：表粒度、主键、允许字段和受控关联。
- 本轮业务确认：默认排除内部客户；最新快照与三个月前比较；最近三个完整月与此前三个完整月比较；同客户部门为默认横向范围；不设置DSO目标天数；不做信用或经营决策。
- 2026-07-21 Profile owner 逐项复核确认：正式应收周转继续使用毛出库分母；平均净经营欠款保留签名值并使用 N+1 月末快照的期初/期末半权重公式；结算完成后仍有正数未结余额的单据不进入历史结算指标；“超账期金额”名称继续沿用已确认的欠款减授信公式；出库—收款对照继续保持出库排除、收款包含内部客户的非对称范围；关注客户按证据通道分别展示，不生成统一风险排名；同类样本不足不设置模型自创的固定数量阈值，证据不足时只展示客户自身历史。

## 生产只读核验（2026-07-16）

- 最近12个完整月存在 112,539 张可识别结算完成时间的外部客户应收单。
- 138 张单据结算天数为负，占 0.12%，范围为 -1 至 -2 天；正式结算指标排除并返回排除数量。
- 仅 2 张单据同时存在结算完成时间和正数未结余额；仅 1 张单据在同单明细中混合开闭状态；正式结算指标排除这类冲突单据。
- 同一应收单的单据时间和结算完成时间在明细间均未发现差异，按非重复应收单计算具备数据基础。
- 最近6个完整月出库和收款月份齐全；最近欠款与账龄月份连续。
- 正欠款、有效出库、收款客户的客户部门缺失率均为 0%，支持同客户部门横向比较。
- 正式12个月DSO所需13个月末欠款快照和12个出库月份已验证齐全。
- 查询工具真实链路已验证：历史结算、结算分布、正式DSO（整体及部门）、出库收款对照、月度趋势、连续期间比较和最新快照与三个月前比较均在只读事务、30秒超时和行数上限内成功执行。
- 当前出库收款对照已改为净出库对净收款：出库侧排除内部客户，收款侧包含内部客户，属于经确认的非对称范围；回答必须披露。
- 2026-07-16：四事实对照已通过生产 RDS 最近三个完整月、只读、`LIMIT 3` 验证，返回净出库、净收款、差额和覆盖率字段。

所有核验仅保留汇总计数和覆盖率，不保存客户、单据或金额明细。

## 已知限制

- 账龄快照与欠款快照不能假设完全勾稽一致，组合回答时必须保持来源分离。
- 大量正欠款行没有匹配授信记录；按已确认规则单列为“无授信有欠款”，不能把缺失授信自动当成零额度混入超账期金额。
- 现有数据不能证明客户经营困难、付款意图、违约概率、争议原因、担保情况或业务动作是否合适。
- 客户当前主数据只用于补充当前属性，不等于历史时点属性。

## 被替代的旧规则

- 旧版30天DSO目标只是分析假设，当前版本不设目标天数。
- 旧版把缺失授信记录按零额度处理的规则已废弃。
- 旧版信用额度、账期建议、压降分配和高中低风险标签不进入当前轻量版本。
